# 每日任务配置说明

本文档记录当前每日任务的服务端配置、奖励参数、进度来源与协议约定。每日任务以服务端为唯一权威；客户端仅展示任务列表和发送领奖请求。

## 1. 当前规则

| 参数 | 当前值 | 说明 |
| --- | ---: | --- |
| 重置时间 | 每天本地 00:00 | 使用服务器 `time.Local` 的自然日，不随农场 demo 时间档缩放。 |
| 固定任务数 | 1 | 每天必定出现。 |
| 随机任务数 | 5 | 从随机任务池中无重复抽取。 |
| 每日任务总数 | 6 | 任务页先展示固定任务，再展示随机任务。 |
| 奖励形式 | 金币 | 通过 `TaskClaim` 直接入账；当前没有任务经验奖励。 |
| 领取次数 | 每项 1 次 | 同一任务重复领取不会重复发奖。 |

## 2. 固定每日任务

| ID | 名称 | 初始进度 | 目标 | 奖励 | `kind` | 完成方式 |
| ---: | --- | ---: | ---: | ---: | --- | --- |
| 4 | 每日登录 | 1 | 1 | 100 金币 | `fixed` | 当天首次读取任务时即完成，玩家可直接领取。 |

## 3. 随机每日任务池

| ID | 名称 | 目标 | 奖励 | `kind` | 进度事件 |
| ---: | --- | ---: | ---: | --- | --- |
| 5 | 浇水 | 10 次 | 200 金币 | `random` | 自己农场成功浇水。 |
| 2 | 收获 | 5 次 | 300 金币 | `random` | 自己农场成功收获。 |
| 3 | 拜访好友农场 | 1 次 | 250 金币 | `random` | 成功进入好友农场。 |
| 1 | 播种 | 6 次 | 200 金币 | `random` | 自己农场成功播种。 |
| 7 | 出售果实 | 1 次 | 150 金币 | `random` | 成功出售仓库果实。 |
| 6 | 施肥 | 1 次 | 100 金币 | `random` | 自己农场成功施肥。 |

## 4. 抽取、存储与重置

1. 玩家请求 `TaskList`，或有可计数玩法事件发生时，后端根据 `(uid, YYYYMMDD)` 计算当天任务。
2. 固定任务直接加入列表；随机池用稳定的 xorshift64 序列按玩家 ID 与日期抽取 5 项。
3. 后端在事务中删除当天未被选中的旧任务行，并以最新目标和奖励 upsert 当前 6 条任务；同一天的重复读取、重连和多实例访问得到相同任务组合。
4. 每日进度保存在 `player_task` 的 `progress`、`target`、`reward_coin` 与 `claimed_at` 字段中；`(uid, logic_day, task_id)` 是唯一键。
5. 未被当天抽中的任务不会显示，也不能领取；该动作发生时不会被视为异常。
6. 下一个服务器本地自然日开始后，新的 `logic_day` 会生成新的固定任务与随机任务组合。
7. 新任务池部署后，玩家当天已经生成的旧版四任务列表会立即迁移为最新列表，不再展示旧任务板；相同 ID 保留未领取进度，已领取任务保持已领取且按新目标显示完成，避免重复发奖。

## 5. 进度与奖励流程

```text
成功玩法动作
  → Gateway / Farm RPC 映射任务 ID
  → Store.AdvanceTask(uid, dayKey, taskID, 1)
  → player_task 原子累加（最多到 target）
  → TaskNotify(9008) 推送最新单项任务

玩家点击“领取奖励”
  → TaskClaim(602, task_id)
  → 检查当天任务、完成进度和 claimed_at
  → 事务内增加金币并写入 claimed_at
  → PlayerDelta(9002) 更新客户端金币
```

任务已完成后，再次触发相同动作不会增加进度，也不会重复推送任务更新。

## 6. WebSocket 协议

任务详情（`kind`、`title`、`target`、`reward_coin`）只由服务端定义并返回；客户端没有任务池、任务 ID 到标题/奖励的映射，也不会为缺字段的任务补默认标题、目标或奖励。不完整的列表项和推送会被忽略，直到收到完整的服务端状态。

### `TaskList`（600）

响应包含当天完整任务列表与下一次刷新时间：

```json
{
  "tasks": [
    {
      "id": 4,
      "day_key": 20260731,
      "kind": "fixed",
      "title": "每日登录",
      "progress": 1,
      "target": 1,
      "reward_coin": 100,
      "claimed": false
    }
  ],
  "reset_at": 1788192000000
}
```

### `TaskNotify`（9008）

服务端在实际推进任务时推送单条任务对象。字段与 `TaskList.tasks[]` 相同，客户端只合并与当前任务板 `day_key` 一致的任务，再按 `id` 更新，不修改金币余额。

### `TaskClaim`（602）

请求：

```json
{ "task_id": 5 }
```

只有当天被抽中、已完成且尚未领取的任务可以成功领取。金币变化以 `PlayerDelta` 为准。

## 7. 调整数值或扩展任务

任务定义集中在 [server/internal/store/task.go](../../server/internal/store/task.go)：

- 固定任务：`fixedDailyTaskDefinitions`
- 随机任务池：`randomDailyTaskPool`
- 每日随机数量：`RandomDailyTaskCount`

新增任务时应同时完成以下事项：

1. 分配一个未使用且稳定的任务 ID，并加入固定列表或随机池。
2. 在 Gateway 与 Farm RPC 的成功动作路径中写入对应的 `AdvanceTask` 调用，确保单机与分片模式一致。
3. 确认 `IsDailyTaskID` 能识别该 ID，以允许 `TaskNotify` 推送。
4. 为抽取稳定性、进度推进、领奖幂等和前端映射补充测试。
5. 同步更新本文档与 [协议文档](protocol.md)。

## 8. 性能与并发策略

- 玩家当天任务首次使用时，在事务中清理未选中的旧任务，并以一条多值 upsert 初始化或校准固定任务与随机任务；`(uid, logic_day, task_id)` 主键继续承担跨实例幂等。
- 每个服务进程只缓存当前自然日已经初始化的玩家。相同玩家的并发首次请求由一个初始化者执行数据库写入，其余请求等待同一结果；跨日自动清空缓存。
- 旧 `daily_login` 兼容映射只随当天首次初始化执行，不在每次播种、浇水等动作中重复查询。
- `AdvanceTask` 的原子更新没有改变行时，表示任务已完成，不再追加读取任务详情；只有实际推进后才读取并推送完整状态。
- 分片模式下，`TaskNotify` 以 `uid + day_key + task_id` 为键在 75ms 窗口内保留最新状态。待发送键最多 4096 个，刷新工作协程最多 16 个；超过上限时丢弃新的提示并记录限频告警，不在玩法请求中同步执行 HTTP 扇出。
- Gateway 的每连接邮箱按 `day_key + task_id` 合并最新状态，因此客户端可能跳过中间进度，但不会把午夜前后的同 ID 任务互相覆盖；完整状态始终可通过 `TaskList` 恢复。
- 客户端同一登录会话中的并发 `TaskList` 刷新复用一条在途请求。领奖后的刷新使用强制模式，避免复用领奖前的旧请求。
