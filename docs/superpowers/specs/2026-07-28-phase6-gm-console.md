# 经典农场 · 期 6 规格：开发 GM 控制台

> 状态：已确认设计，待实现计划
> 工程规范：`2026-07-26-engineering-standards.md`
> 前置：期 5 工程化加固已合入 `main`

---

## 1. 目标

提供只在开发环境可用的 GM 控制台，用于精细编辑任意玩家的权威游戏数据、切换查看目标农场、预览客户端昼夜画面，并将现有 Net 诊断合并到同一个可折叠面板。

成功标准：

1. 开发者可按用户名精确查找任意玩家，切换后客户端以目标农场的权威快照重建画面，并持续接收该农场 Delta。
2. 所有 GM 写操作经目标玩家 Actor 串行执行、同步持久化，并使正在查看目标农场的客户端立即得到一致状态。
3. 生产环境不注册 GM 路由、不渲染 GM UI；普通玩家 session、好友关系或现有 debug 时间接口不能取得 GM 权限。
4. 昼夜切换仅影响当前客户端画面，不推进服务端时间、不改变作物进度或其他玩家状态。

## 2. 非目标

- 不提供生产运营后台、角色权限管理、多管理员协作或跨环境 GM。
- 不把 GM 操作加入正式 WebSocket 协议或面向普通客户端的命令/错误码。
- 不以直接修改 `farm.Aggregate` 导出字段替代领域操作；每个写操作必须维护序列、快照/Delta 和持久化语义。
- 不实现图鉴编辑、强制踢线、跨分片批量操作；这些不在当前服务端权威模型中，另开规格。
- 不改变服务端逻辑时间；已有 `/api/debug/advance` 保持其原有冒烟职责，不被 GM UI 复用。

## 3. 环境与安全

### 3.1 双重门控

服务端仅在同时满足以下条件时注册 `/api/gm/v1/`：

- `FARM_ENV=dev`
- `FARM_ENABLE_GM=1`

客户端仅在 `import.meta.env.DEV` 且开发 GM 配置存在时加载 GM 控制台。任一条件不满足时，路由和 UI 必须不存在，而非返回“禁用”页面。

### 3.2 GM 身份

- 服务端读取高熵 `FARM_GM_SECRET`；缺失、默认值或长度不足时，开发 GM 不启动。
- 客户端开发配置 `VITE_FARM_GM_SECRET` 仅用于本机开发，禁止写入生产构建配置或示例中的真实值。
- 每个 GM HTTP 请求使用 `Authorization: Bearer <GM secret>`；服务端使用常量时间比较。
- GM 路由限制请求体大小、记录操作者来源、目标 UID、操作名、请求 ID、结果与错误；秘密和完整背包内容不得写入日志。

### 3.3 权威写入

- 单玩家写入必须路由到目标 Farm 分片，在 `actor.Runtime.Do(targetUID, ...)` 内执行。
- 会改变 Aggregate 的操作必须调用 `FarmActor.RequireFlush()`；失败时不得留下局部写入。
- 禁止通过 `Store.LoadFarm()` 后直接保存在线玩家，避免覆盖驻留 Actor 的权威内存。
- GM 视图授权是短期、单次、绑定 GM session 与目标 UID 的 grant；不可用好友权限或普通 session 越权进入任意农场。
- 一次 GM mutation 只能修改一个数据域：农场 Aggregate、好友、任务或邮件。控制台必须将跨域目标拆成多次独立操作，不实现跨域账本或补偿。

## 4. GM HTTP 与视图协议

### 4.1 API 形状

所有响应使用：

```json
{ "err": 0, "data": {}, "request_id": "opaque-id" }
```

接口：

| 路径 | 用途 |
| --- | --- |
| `GET /api/gm/v1/players?username=` | 精确搜索玩家，返回 uid、用户名、昵称与轻量状态 |
| `GET /api/gm/v1/players/{uid}/snapshot` | 通过目标 Actor/分片获取完整 GM 快照 |
| `POST /api/gm/v1/players/{uid}/mutations` | 执行一个具名 GM 操作，返回目标、最新快照与 `farm_seq` |
| `POST /api/gm/v1/players/{uid}/view-grants` | 创建一次性查看 grant |

GM 变更请求必须使用具名 `kind` 和受类型约束的 `payload`，禁止通用“任意字段 patch”或在同一请求中混合多个数据域。每次 mutation 携带客户端生成的 `request_id`；服务端返回目标的完整快照以驱动 GM 面板立即刷新。

### 4.2 目标农场切换

1. 面板按用户名解析目标 UID，并创建目标 view grant。
2. 客户端在现有 `EnterFarm` 请求中携带仅开发环境识别的可选 `gm_view_grant`；Gateway 校验后订阅目标农场房间。
3. WS 返回的 `EnterFarmResponse` 必须复用 `applyAuthoritativeFarmEnter()`，覆盖本地镜像、更新 `setFarmView()`、递增视图 generation，并刷新界面。
4. 离开 GM 目标时，客户端重新进入自己的农场；在途 SyncFarm/Delta 由现有视图 generation 规则丢弃。

## 5. 操作集

控制台必须将操作按组展示；每个可破坏操作都要显示目标用户名，并要求二次确认。

### 5.1 玩家与背包

| 操作 | 粒度 |
| --- | --- |
| 金币、经验 | 增加、减少、设置 |
| 等级 | 通过“设置经验并重算等级”实现，不直接写等级 |
| 物品 | 按合法 ItemKey 增加、减少、设置数量、清空单项、清空全部 |
| 基础状态 | 查看 uid、昵称、等级、金币、经验、背包与仓库摘要 |

数量不得为负；扣除不得下溢；未知 ItemKey 必须拒绝。物品操作后更新快照中的背包和仓库投影。

### 5.2 农场与地块

| 操作 | 粒度 |
| --- | --- |
| 农场 | 设置已解锁地块数、重置整场、批量浇水、批量清草、批量清虫、批量成熟、批量枯萎 |
| 单地块 | 翻地、清空、指定作物、指定成长阶段、浇水、清草、清虫、设置健康、施肥掩码、被偷数、强制收获 |

单地块操作先执行 `AdvanceAll(now)`，再验证地块索引、作物配置、状态与数值边界；所有成功变更增加 `FarmSeq` 并生成 `FarmDelta`。整场重置和批量修改必须作为一个 Actor 操作提交，失败不得部分成功。

### 5.3 宠物、社交、任务与邮件

| 分组 | 操作 |
| --- | --- |
| 宠物 | 授予/移除狗、启用狗、设置等级、狗粮与狗盆状态、清空拦截统计 |
| 社交 | 查看好友、按用户名添加好友、解除好友 |
| 任务 | 查看任务、设置指定任务进度、重置目标玩家当日任务状态 |
| 邮件 | 查看邮件、投递带金币或物品附件的邮件、删除指定邮件、清空全部邮件、重置每日登录领取状态 |

任务与邮件持久化不在 Farm Aggregate 内；对应 GM 写必须使用事务化 Store API，并在成功后刷新目标玩家面板。邮件附件变更不得绕过邮件领取事务。

## 6. 客户端交互与画面预览

### 6.1 面板结构

- 默认收起为右下角 `GM` 浮动按钮；点击后展开抽屉式面板。
- 顶部固定显示目标用户名、UID、切换输入框、返回自己农场按钮和关闭按钮。
- 中部按“玩家 / 背包 / 农场 / 地块 / 宠物 / 社交、任务与邮件 / 画面 / Net 诊断”折叠分组。
- 每项操作有明确字段标签、输入约束、执行按钮、成功/失败结果与最近操作摘要。
- 危险区使用显著样式；清空、重置、删除和批量覆盖需输入目标用户名后才能确认。

### 6.2 画面时间

`FarmScene.setDayPhase(phase)` 是纯客户端渲染入口。面板提供：

- 清晨、白天、黄昏、夜晚预设；
- 跟随游戏画面（默认）；
- 当前预览状态说明。

预览模式启用时，游戏 `tick()` 不得覆盖所选 phase；恢复“跟随游戏画面”后立即按正常 tick 计算显示。该状态不持久化、不发网络请求。

### 6.3 Net 诊断

移除独立 `DevNetPanel` 的页面位置，将其数据迁入 GM 的“Net 诊断”分组，保留 online 状态、UID、金币、经验、已解锁地块、好友数和 NetClient 连接状态。

## 7. 错误与审计

- 目标不存在、grant 过期、非开发环境、未授权、非法参数、未知 ItemKey、地块状态不允许、持久化失败必须给出可操作的 GM 错误信息。
- 写操作只在领域验证完全通过后提交；失败不改变 Aggregate、任务、邮件或好友关系。
- 记录操作审计日志，不记录 `FARM_GM_SECRET`、Authorization 值、密码哈希或完整 session token。

## 8. 验收与测试

### 8.1 服务端

- 非 `dev` 环境或未启用 `FARM_ENABLE_GM=1` 时，GM 路由不存在。
- 缺失/弱 GM secret 拒绝启动；错误 secret 返回 401。
- 搜索、目标切换 grant、grant 重放/过期/目标不匹配均有覆盖。
- 资源、背包、地块、宠物、好友、任务、邮件的每种 mutation 覆盖成功、非法参数、失败无副作用、同步落盘。
- 分片路由下对目标 Actor 写入后，房间 Delta 与目标玩家个人刷新正确送达。

### 8.2 客户端

- GM 面板仅 DEV 挂载；收起/展开、分组展开、目标切换、危险确认和错误显示可测。
- 切换目标后只应用最新权威快照；旧视图的 Delta/SyncFarm 不污染当前界面。
- 画面预览锁定 phase，恢复跟随后重新由 tick 驱动。
- Net 诊断只在 GM 面板显示。

### 8.3 验收剧本

1. 以开发配置启动，登录 A；打开 GM，搜索 B 并切换到 B 的农场。
2. 修改 B 的金币、背包和单块地块；刷新页面后数据仍存在，正在查看 B 的客户端立即同步。
3. 执行批量成熟和强制收获；检查产物、FarmSeq 与 Delta。
4. 发放狗粮、修改狗状态、投递附件邮件、设任务进度；重新打开对应 UI 确认权威数据。
5. 选择夜晚预览、观察画面；恢复跟随后画面重新自动变化，服务端作物进度不受影响。
6. 使用生产或未启用 GM 的配置启动，确认没有 GM HTTP 路由与前端入口。
