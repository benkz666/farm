## 左侧新结构

以“前端（Client）”和“服务器（Server）”两条纵向生命线构成从上到下的通信时序图：

1. 服务器持有 `Snapshot(seq = 100)` 权威状态基线，通过“首次加载 / 重连”发送给前端；前端记录 `farm_seq = 100`。
2. `FarmDelta 环形缓冲` 固定放在服务器泳道中，展示 `Δ101 → Δ102 → Δ103`，并标注“仅保留最近 N 条”。
3. 把增量更新直接写在服务器到前端的通信箭头上：
   - `FarmDelta(seq = 101)`：前端应用成功，推进到 `farm_seq = 101`
   - `FarmDelta(seq = 102)`：虚线箭头、红叉和“网络丢失”
   - `FarmDelta(seq = 103)`：前端发现“期望 102，却收到 103”
4. 前端向服务器发送 `SyncFarm(from_seq = 101)`。
5. 服务器检查环形缓冲是否覆盖 `102、103`：
   - 覆盖：绿色箭头补发 `FarmDelta 102、103`
   - 已淘汰：橙色箭头返回 `Snapshot(seq = 103)`
6. 前端按序应用并重新收敛到 `farm_seq = 103`。

左侧页脚结论：“在线只传增量 · 缺口优先补发 · 必要时快照兜底”。

## 绘制约束

生命线清晰、时间严格向下；通信箭头粗且方向明确；前端和服务器图标加大加粗；环形缓冲必须在服务器一侧；禁止省略步骤、乱码、UML 模板腔、3D 和无关装饰。
